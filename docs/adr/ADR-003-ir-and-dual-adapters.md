# ADR-003: Lightweight IR, Shared Normalization Layer & Safe Save Semantics

- **Status:** Accepted (2026-11-22; Updated 2026-11-23 for IR `v1.1`)
- **Target Versions:** `Grafana OSS v12.4.15 / v13.3.1`, `@grafana/scenes v9.3.0`, `@grafana/grafana-foundation-sdk v0.0.22`

## Context
Having an LLM generate raw Grafana Dashboard JSON directly risks schema drift, arbitrary datasource UID injection, HTML/JS injection, and divergence between live previews and saved dashboards. Moreover, the legacy `/api/dashboards/db` endpoint can still overwrite an existing dashboard even with `id: null` and `overwrite: false` if a colliding `uid` happens to match the stored `version` (verified in `grafana v12.4.15` `pkg/services/dashboards/service/dashboard_service.go` L839–862). In addition, Grafana 13 formally deprecates legacy `/api` endpoints in favor of `/apis`.

## Decision
1. **Canonical JSON Schemas (`schemas/dashboard-ir.schema.json`, `schemas/dashboard-patch.schema.json`) — IR `v1.1` (backward-compatible with `v1.0`):**
   - The LLM generates only a constrained Dashboard IR (`1.0` or `1.1`) or targeted Patch. `datasourceRef` is restricted to the logical constant `"selected_prometheus"`.
   - IR `v1.1` expands visualization support to 7 allowlisted panel types (`timeseries`, `stat`, `table`, `gauge`, `bargauge`, `piechart`, `state-timeline`), bounded multi-query panels (1–3 queries per panel with refIds `A`–`C`, mutually exclusive with single-query `query`), and scoped dashboard template variables (max 4, `query` via `label_values(...)` or bounded `custom` options) validated safely in `pkg/promql`.
   - Bidirectional contract parity across JSON Schema, TypeScript (`src/ir`), and Go (`pkg/ir`) is enforced automatically by `scripts/verify-schema-sync.mjs` (including string-only enum verification for `grafana-llm-app`'s `go-openai/jsonschema.Definition`).
2. **Single Shared Normalization Layer (`NormalizedDashboardSpec`) + Two Thin Adapters:**
   - Panel layout (`gridPos`), units, threshold steps (preserving non-zero first steps by prepending a `green` base step), resolved datasource references, multi-query targets (`refId: "A" | "B" | "C"`), and template variables are computed once in `src/spec/normalize.ts`.
   - `src/spec/toScene.ts` (using only public `@grafana/scenes` APIs, including `SceneVariableSet` and `VariableValueSelectors`) and `src/spec/toFoundation.ts` (`@grafana/grafana-foundation-sdk`) remain thin adapters whose output parity across all 7 panel types, multi-query panels, and variables is continuously verified by `src/spec/parity.test.ts`.
3. **Optional Safe Import + Create-Only Default Save API (`v1beta1`) with Opt-In Revision-Checked Update:**
   - Existing Grafana dashboards can be deterministically imported (`src/import/importDashboard.ts` + `POST /jobs/import`) into a constrained IR `v1.1` draft with explicit skipped-item reporting, HTML/control-char stripping, datasource rebinding to `selected_prometheus`, and full backend IR + PromQL AST safety validation.
   - Default dashboard creation always uses `POST /apis/dashboard.grafana.app/v1beta1/namespaces/{namespace}/dashboards`, verified on both Grafana `v12.4.15` and `v13.3.1` (where `apps/dashboard/pkg/apis/dashboard/v1beta1/register.go` aliases `v1` with an identical schema). Dashboard UIDs are freshly generated by the app; on `409 Conflict`, create-only save never retries with `PUT`.
   - For dashboards imported from `v1beta1` with a captured `metadata.resourceVersion`, users may explicitly opt in to a revision-checked update (`PUT /apis/dashboard.grafana.app/v1beta1/namespaces/{namespace}/dashboards/{uid}` carrying `metadata.resourceVersion`). Missing `resourceVersion` is rejected client-side, and HTTP `409`/`412` fails safely without force-overwriting.
   - Folder listing prioritizes `/api/folders?permission=Edit` for write-permission filtering and falls back to `/apis/folder.grafana.app/v1beta1/namespaces/{namespace}/folders` if legacy `/api` endpoints return `404`/`410`.
   - Both create and opt-in update enforce `spec.revision === previewedRevision` and an in-flight double-click lock. Saved and exported Dashboard JSON never embeds chat history, credentials, unnecessary metadata, or raw metric samples.
