# ADR-003: Lightweight IR, Shared Normalization Layer & Create-Only Save API

- **Status:** Accepted (2026-11-22)
- **Target Versions:** `Grafana OSS v12.4.15 / v13.3.1`, `@grafana/scenes v9.3.0`, `@grafana/grafana-foundation-sdk v0.0.22`

## Context
Having an LLM generate raw Grafana Dashboard JSON directly risks schema drift, arbitrary datasource UID injection, HTML/JS injection, and divergence between live previews and saved dashboards. Moreover, the legacy `/api/dashboards/db` endpoint can still overwrite an existing dashboard even with `id: null` and `overwrite: false` if a colliding `uid` happens to match the stored `version` (verified in `grafana v12.4.15` `pkg/services/dashboards/service/dashboard_service.go` L839–862). In addition, Grafana 13 formally deprecates legacy `/api` endpoints in favor of `/apis`.

## Decision
1. **Canonical JSON Schemas (`schemas/dashboard-ir.schema.json`, `schemas/dashboard-patch.schema.json`):**
   - The LLM generates only a constrained Dashboard IR or targeted Patch. `datasourceRef` is restricted to the logical constant `"selected_prometheus"`.
   - Bidirectional contract parity across JSON Schema, TypeScript (`src/ir`), and Go (`pkg/ir`) is enforced automatically by `scripts/verify-schema-sync.mjs`.
2. **Single Shared Normalization Layer (`NormalizedDashboardSpec`) + Two Thin Adapters:**
   - Panel layout (`gridPos`), units, threshold steps (preserving non-zero first steps by prepending a `green` base step), resolved datasource references, and query targets (`refId: "A"`) are computed once in `src/spec/normalize.ts`.
   - `src/spec/toScene.ts` (using only public `@grafana/scenes` APIs) and `src/spec/toFoundation.ts` (`@grafana/grafana-foundation-sdk`) remain thin adapters whose output parity is continuously verified by `src/spec/parity.test.ts`.
3. **Create-Only Save API (`v1beta1`):**
   - Dashboard creation uses `POST /apis/dashboard.grafana.app/v1beta1/namespaces/{namespace}/dashboards`, verified on both Grafana `v12.4.15` and `v13.3.1` (where `apps/dashboard/pkg/apis/dashboard/v1beta1/register.go` aliases `v1` with an identical schema).
   - Folder listing prioritizes `/api/folders?permission=Edit` for write-permission filtering and falls back to `/apis/folder.grafana.app/v1beta1/namespaces/{namespace}/folders` if legacy `/api` endpoints return `404`/`410`.
   - Dashboard UIDs are always freshly generated by the app (never supplied by the LLM). On `409 Conflict`, the saver never retries with `PUT` or overwrites; it also enforces `spec.revision === previewedRevision` and an in-flight double-click lock.
   - Saved and exported Dashboard JSON never embeds chat history, credentials, unnecessary metadata, or raw metric samples.
