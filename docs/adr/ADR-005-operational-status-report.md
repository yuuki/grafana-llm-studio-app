# ADR-005: On-Demand Operational Status & Incident Analysis Report

- **Status:** Accepted (2026-11-27; revised after adversarial design review)
- **Target Versions:** `Grafana OSS v12.4.15 / v13.3.1`, `grafana-llm-app v1.0.8 (12.4.x) / v1.2.0 (13.x)`, `llmclient v0.20.0`, `grafana-plugin-sdk-go v0.278.0`

## Context
Operators using `yuuki-llmstudio-app` can already generate, refine, import, preview, and save Prometheus/VictoriaMetrics dashboards. However, during active incidents or routine health checks, operators still have to manually correlate Grafana Alerting states with dashboard metric anomalies across time windows and summarize findings for triage or post-incident handoffs.

Adding LLM-powered operational analysis introduces five concrete risks that must be structurally controlled:
1. **Auth & Data Boundary Regression:** Querying Prometheus or Grafana Alerting from the Go backend with `llmServiceAccountToken` would violate [ADR-002](ADR-002-auth-boundaries-and-oss-rbac.md) and break user-session scoping.
2. **Hallucination, Truncation & Untrusted Telemetry Injection:** Raw time-series arrays inflate token usage and invite arithmetic errors on mid-sized or local vLLM models; alert labels/annotations and panel titles are untrusted strings capable of prompt injection or leaking embedded credentials/URLs; oversized output schemas trigger `finish_reason == "length"` (`ErrOutputTruncated`) under default `maxOutputTokens=2048`.
3. **Unvalidated Query Leakage:** Allowing a report LLM response to emit arbitrary PromQL/MetricsQL directly into the UI would bypass the catalog-grounded AST validation pipeline established in [ADR-003](ADR-003-ir-and-dual-adapters.md).
4. **Configuration, Rolling-Upgrade & DML-Only Storage Drift:** Adding mandatory settings keys or breaking Redis/PostgreSQL job store schemas (including least-privilege DML-only PostgreSQL deployments) would disrupt existing Dashboard Studio deployments.
5. **Dual-Version Frontend Routing Pitfalls:** Grafana `12.4.15` (React 18, React Router v6) and `13.3.1` (React 19, React Router v7) share `react-router` (not `react-router-dom`), requiring strict externalization and shared-API discipline.

## Decision

### 1. On-Demand Browser-Side Evidence Collection (Preserving ADR-002)
- **Execution Model:** Status analysis is strictly **on-demand** and initiated interactively from the browser. Background scheduled reports and automated external notifications (Cron/Slack) are explicitly out of scope because they conflict with ADR-002's prohibition on non-session backend datasource/alert queries.
- **MVP Evidence Sources (User Session Only):**
  1. **Grafana Unified Alerting:** Active/suppressed/unprocessed alert instances (`GET /api/alertmanager/grafana/api/v2/alerts`) and alerting rule evaluation states (`GET /api/prometheus/grafana/api/v1/rules?limit_alerts=20`, filtering `type === "alerting"` and capturing `firing`, `recovering`, `pending`, `error`, `nodata`, `unknown`). Firing rules are cross-referenced via `__alert_rule_uid__` to avoid double-counting while still capturing alerts when an external Alertmanager is configured.
  2. **Dashboard-Anchored Performance Metrics (Optional):** Queries extracted from a saved Grafana dashboard via a **dedicated read-only extractor (`src/report/dashboardExtractor.ts`)** rather than `convertGrafanaDashboardToIR` (so Grafana built-in `$__rate_interval`/`$__interval`/`$__range`, default `null` datasources, `${DS_*}` variables, and panels beyond Studio's 6-panel IR cap work cleanly). Every resolved query target UID is verified against `allowedDatasourceUids` before calling `/api/ds/query` under an overall collection deadline (`25s`), `maxConcurrentQueries`, and `validationTimeoutSeconds`. The browser deterministically computes compact statistical summaries (`latest`, `avg`, `p95`, `min`, `max`, expected-step `missingRatio`, spike timestamp, raw threshold breach, query error/nodata) for the selected window (`15m`, `1h`, `6h`, `24h`) and compares them against a configurable baseline window (default: `preceding`; toggleable to `24h_ago` or `none`, skipping baseline queries when the current window errors/times out).
  3. **Graceful Partial-Failure & Healthy-State Accounting:** Unavailable or forbidden sources (e.g., HTTP `403`/`404`) and truncation events are recorded as explicit `collectionWarnings` with deterministic IDs (`ev-warn-*`). When alerting succeeds with 0 firing alerts, 0 abnormal rules, and no dashboard metrics, collection still succeeds (`collectionStatus.alertsChecked || collectionStatus.rulesChecked`), avoiding false `422` errors on healthy clusters.
- **Deferred to Phase 2:** Scope-only 2-step AI query planning (without selecting a dashboard), Prometheus/VictoriaMetrics datasource-managed alerts (`/api/v1/alerts`), alert/deploy annotations (`/api/annotations`), and multi-signal extensions (Loki/Tempo).
- **Defense-in-Depth Secret Redaction, URL Scrubbing & Transparency:**
  - By default, a single click executes `Collect -> Client-side secret/URL redaction -> Analyze`, displaying all collected evidence alongside the report with clickable `ev-*` links. An opt-in **"Preview evidence before sending"** checkbox allows manual two-step approval prior to backend submission.
  - Because browser redaction is not a security boundary, the Go backend executes the **same** secret redaction and URL scrubbing (`https?://...` -> `[URL]`) on all untrusted input text before prompt construction and again on validated output before persisting to `JobStore`.
- **Browser State Clearing:** All collected evidence, previews, and active report states remain strictly in browser memory and are aborted/cleared on organization switch, datasource switch, logout, or page unmount.

### 2. Strictly Grounded `StatusReportIR` & Fail-Closed Validation
- **Canonical Schema (`schemas/status-report.schema.json`):** The LLM returns only a compact structured JSON report conforming to `StatusReportIR` (`schemaVersion: "1.0"`), never free-form Markdown or raw HTML/URLs. Array and rune caps are sized conservatively to fit comfortably inside the default `maxOutputTokens: 2048` budget (with `>= 4096` recommended for Japanese or reasoning models).
- **`grafana-llm-app` Protocol Compatibility ([ADR-001](ADR-001-llm-routing-via-grafana-llm-app.md)):** The schema uses string-only `enum` values, no `oneOf`/`anyOf`, no `const`/`format`, no array `type`, and `Strict: false` in `json_schema` mode (with system-prompt schema embedding in `json_object` mode). Bidirectional parity across JSON Schema, TypeScript (`src/ir/`), and Go (`pkg/ir/`) is verified by `scripts/verify-schema-sync.mjs`, and real container wire relay is verified via `make verify-llm-protocol`.
- **Mandatory Evidence Grounding (Fail-Closed):** Every alert (`ev-alert-*`), rule anomaly (`ev-rule-*`), metric summary (`ev-metric-*`), collection warning (`ev-warn-*`), and healthy-check summary (`ev-status-*`) has a deterministic ID. Every `timeline`, `findings`, and `hypotheses` item must cite `>= 1` unique valid ID from the request bundle; `overallStatus` of `"degraded"` or `"critical"` requires `len(findings) >= 1`. Go deterministically rejects any schema violation, missing required array, duplicate ID, or non-existent `evidenceId` with `ErrInvalidReportIR` (fail-closed, zero auto-repair loops, zero silent citation stripping).
- **Prose-Safe Content Hygiene:** Output validation rejects HTML tag patterns (`(?i)<\s*/?\s*[a-z][a-z0-9-]*[\s/>]`), forbidden URI schemes (`http://`, `https://`, `javascript:`, `vbscript:`, `data:`), and control characters without falsely rejecting benign inequality operators such as `"p95 < 50ms -> > 500ms"`.
- **Safe Studio Handoff Without Raw PromQL in Reports:** `StatusReportIR` may include a bounded plain-text `suggestedInvestigationIntent` (no raw PromQL, no LLM-invented datasource UIDs). Clicking **"Investigate in Studio"** navigates via `@grafana/runtime`'s `locationService` to `/a/yuuki-llmstudio-app` using the user's selected datasource/scope context plus `intent`, where `StudioPage` safely consumes and strips the query parameters once on mount without auto-firing queries.
- **Report Output Language:** Defaults to the user's active Grafana locale (`ja` or `en` via `getActiveLocale()`), with an explicit per-request selector (`ja` / `en`) in the Report UI. Deterministic Markdown export formats section headings from `LOCALE_RESOURCES[reportLanguage]` so headings always match the report body language.

### 3. Unified Routing, Job Lifecycle & Storage Compatibility
- **LLM Routing & API:** Analysis executes via `POST /jobs/analyze` (reusing `GET /jobs/{id}` and `POST /jobs/{id}/cancel`), routed exclusively through `pkg/llm.Client` (`AnalyzeStatus`) -> `llmclient` -> `grafana-llm-app` (with explicit dev-only `MockClient` support). Pre-flight errors return HTTP `400`/`403`/`422`/`429`/`503`; post-flight LLM/validation failures persist `status: "failed"` and return HTTP `502` (or SSE `event: error` with status `502`); calling `/patch`, `/repair`, or `/undo` on a report job returns `409 Conflict` (`ErrWrongJobKind`).
- **Zero New Admin Settings Keys:** Reuses existing `jsonData` settings (`allowedDatasourceUids`, `maxConcurrentQueries`, `validationTimeoutSeconds`, `maxOutputTokens`, `llmTimeoutSeconds`, `jobDeadlineSeconds`, `maxConcurrentJobs`, `enableSseProgress`, `jobTtlMinutes`). Note that plugin health checks (`/health`, `CheckHealth`) continue to require at least one configured `allowedDatasourceUids` entry.
- **Owner-Isolated Ephemeral Persistence:** Validated `StatusReportIR` outputs are persisted in `JobStore` strictly under `(OrgID, UserLogin)` ownership for `jobTtlMinutes` (supporting SSE disconnect recovery via `GET /jobs/{id}`). Raw input evidence bundles are **never** persisted in `JobStore`. `Cancel` on a terminal report job is a safe no-op, and empty `queryKind` is not coerced to `"promql"` for report jobs. Long-term retention and sharing use client-side deterministic Markdown and JSON export.
- **HA Rolling-Upgrade & Least-Privilege PostgreSQL Strategy:**
  - `RedisStore`: Stores report metadata/payloads in additive optional hash fields (`job_kind`, `report_json`) while leaving `current_ir_json` empty (`""`). Existing Studio jobs remain 100% compatible across mixed v1/v2 replicas; report job `GET /jobs/{id}` recovery requires sticky routing or completed rollout across all replicas.
  - `PostgresStore`: Fresh installs create `job_kind TEXT NOT NULL DEFAULT ''` and `report_json TEXT NOT NULL DEFAULT ''` in `CREATE TABLE IF NOT EXISTS`. On existing tables, startup probes `pg_attribute` for **both** columns (`count == 2`). If absent and DDL is permitted, it applies `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` in a guarded operation (catching `42501` without aborting `ensureSchema`). For unmigrated DML-only tables, `supportsReportStorage` stays `false`, existing Studio SQL queries omit the new columns and continue uninterrupted, and `POST /jobs/analyze` re-probes (rate-limited) before failing with `503` (`ErrReportStorageMigrationRequired`; DDL hint shown to `Admin` only, generic message to `Viewer`).
- **Transport Retries & SSE ([ADR-004](ADR-004-non-streaming-mvp-and-sse-deferral.md)):** Keeps at most 1 transport retry for retryable `502`/`503`/`504` (and wrapped `500`) errors, zero automatic semantic repairs, and optional decoupled SSE stage events (`operation: "analyze"`, stages `analyzing` -> `validating_report` -> terminal) gated by `enableSseProgress`, with `studioClient.ts` recognizing active report statuses during disconnect recovery.

### 4. Standalone Navigation Page & Dual-Version Routing
- **Plugin Manifest (`src/plugin.json`):** Adds an independent navigation entry under `includes` (`path: "/a/yuuki-llmstudio-app/reports"`, `role: "Viewer"`, `addToNav: true`). Because Grafana reads `plugin.json` only at startup, deploying this feature requires restarting Grafana (explicitly noted in release notes and PR checklist). No changes are made to `id`, `type`, `executable`, or `iam.permissions`.
- **Frontend Routing (`react-router`):** `package.json` declares `"react-router": "6.30.6"` directly (replacing unused `react-router-dom`), `scripts/verify-bundle.mjs` enforces `'react-router'` in `requiredExternals`, and `AppRoot` uses only the v6/v7 common subset (`Routes`, `Route`) with relative child routes (`path="reports"`) and `<PluginPage>`.

## Consequences
- **Positive:** Preserves all existing security boundaries (ADR-001 through ADR-004), keeps `AppConfig` and `iam.permissions` unchanged, prevents hallucinated citations and secret/URL leakage via defense-in-depth sanitization and fail-closed Go validation, works offline/air-gapped on vLLM, and connects safely into Dashboard Studio without exposing unvalidated PromQL.
- **Trade-offs:**
  - Upgrading requires a Grafana restart for the new navigation item in `src/plugin.json`.
  - Pre-created DML-only PostgreSQL deployments require a single additive DDL (`ALTER TABLE <schema>.<prefix>jobs ADD COLUMN IF NOT EXISTS job_kind TEXT NOT NULL DEFAULT '', ADD COLUMN IF NOT EXISTS report_json TEXT NOT NULL DEFAULT '';`) to enable report jobs; Dashboard Studio continues working even before migration.
  - Report jobs share the org/user `JobStore` capacity limits (`defaultMaxJobs=200`, `defaultMaxJobsPerUser=20`), so heavy report generation can evict idle unsaved Studio drafts under high load.
  - Scope-only automated metric query planning, datasource-managed alerts, and annotations are deferred to Phase 2; scheduled unattended reports remain out of scope unless a future ADR defines dedicated non-session read-only access controls.
